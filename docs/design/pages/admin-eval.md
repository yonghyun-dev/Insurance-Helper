# 운영자 평가 셋 결과 대시보드 명세서

- 라우트: `/admin/eval` (인증 필요)
- 스프린트: 11+ (별도 sub-project)
- 우선순위: ★ (CI 회귀 자동화 후)
- 관련: [agent-architecture.md](../agent-architecture.md), `eval/` 디렉토리 (Sprint 8 골격)

## 1. 목적

운영자가 평가 셋 회귀 결과를 시각적으로 확인 + 시나리오별 통과율 트렌드 모니터링. CI 자동화 (Sprint 11) 와 연동해 PR 마다 자동 업데이트.

## 2. 사용자 시나리오

1. **신규 배포 전** — 평가 셋 통과율 확인 (전체 + 시나리오별)
2. **데모 갭 4건 (#C/#D/#E/#F) 회귀 모니터링** — 항상 통과 유지 확인
3. **LLM 모델 변경 시** — gpt-4o-mini → gpt-4o 변경 시 통과율 비교

## 4. 컴포넌트 분해

| 컴포넌트 | 역할 |
|:--|:--|
| `<AdminHeader>` | admin-audit.md 와 공통 |
| `<EvalSummary>` | 최근 실행 메타 (시간, PR 링크, 통과율) |
| `<EvalTrendChart>` | 30일 통과율 라인 차트 |
| `<EvalScenarioTable>` | 시나리오별 결과 표 + 클릭 가능 |
| `<EvalScenarioDetail>` | 단일 시나리오 상세 (모달) — 실제 응답 / 기대 응답 diff |
| `<RunNowButton>` | "지금 실행" — 수동 트리거 (옵션) |

## 5. 인증

admin-audit.md 와 동일. 단 `evaluator` 역할 추가 가능 (eval 만 보고 audit 못 봄).

## 6. 데이터

- 백엔드 신규 API:
  - `GET /api/v1/admin/eval/latest` — 최근 결과
  - `GET /api/v1/admin/eval/trend?days=30` — 트렌드
  - `GET /api/v1/admin/eval/scenario/{id}` — 시나리오 상세
  - `POST /api/v1/admin/eval/run` — 지금 실행 (옵션)

- 데이터 저장: PostgreSQL `eval_run` 테이블 (Sprint 11 추가) — 매 CI 실행 결과 1 row

## 7. 접근성

차트는 데이터 표 형태로도 제공 (스크린리더 — `aria-label` 에 통과율 명시).
