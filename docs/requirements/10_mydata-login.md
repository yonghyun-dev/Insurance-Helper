# REQ-10: 마이데이터 연동 + 로그인 시스템

- 요청일: 2026-05-26
- 상태: 분석 완료, 설계 대기
- 스프린트: 14
- 출처: 챔피언 제안서 (`구현제안서_챔피언_디포커스AI.docx`) "Data Layer — 마이데이터·공공데이터 API 자동 수집" 요구

## 요청 원문

> 사용자 정보 같은 경우는 api 신청을 하면 검사 기간이 있어서 우선을 어떻게 api가 오는지 분석해서 이걸 기준으로 더미 데이터를 한번 만들어보자. 이게 있을려면 로그인 시스템도 필요하긴 하겠다.

## 핵심 목표

마이데이터 API 발급 검증 대기 기간(1~3개월) 동안 API 응답 스키마 기반 **더미 데이터 fixture** 로 백엔드·UI·테스트를 선행 구축한다. 더미 ↔ 실 API 교체는 단일 어댑터 인터페이스로 수렴.

본인 인증이 필요하므로 **로그인 시스템** 을 동시 도입한다.

## 사용자 시나리오

1. 사용자가 웹 UI 첫 진입 시 **"로그인" 또는 "비로그인 시작"** 선택
2. 로그인 선택 시 → OAuth/자체 JWT/마이데이터 본인인증 중 1종 (Sprint 14 진입 시 결정)
3. 로그인 후 → "내 보험 가져오기" 버튼 → 마이데이터 어댑터 호출 → 가입 상품 자동 표시
4. 채팅 진입 시 → 보험사·상품·상품 버전이 자동 슬롯에 채워진 상태 → 사용자는 사고 정보만 입력

## 기술 결정 (Sprint 14 진입 시 확정)

### 인증 방식 — [확인 필요]

| 옵션 | 장점 | 단점 |
|:--|:--|:--|
| 자체 JWT (FastAPI + python-jose) | 단순, 의존 외부 0 | 비밀번호 관리 부담 |
| OAuth (카카오/네이버) | 사용자 친숙, 신원 검증 위임 | 외부 OAuth 앱 등록 필요 |
| 마이데이터 본인 인증 위임 | 마이데이터 흐름 일치 | 본인 인증 비용 발생 |

### 더미 데이터 셋업 위치

- `tests/fixtures/mydata/` — pytest fixture + dev 시드용
- `app/external/mydata/_dummy_data.json` — 런타임 더미 어댑터 응답

### 로그인 후 비로그인 흐름 회귀 보장

- 모든 sessions API 가 인증 헤더 옵셔널 → 로그인 시 user_id 기록 / 비로그인 시 None
- 로그인 시에만 마이데이터 prefill 활성

## 의존성
