# REQ-16: 다중 실손 가입현황-우선 플로우 + 비례분담 설명

- 요청일: 2026-07-08
- 상태: 구현 중
- 스프린트: 30
- PM: [PM-36](../pm/36_multi-insurance-status-flow.md)

## 요청 원문
> 한 사람이 여러 보험에 가입되어 있고 어떤 보험사에 맡기는 게 이득인지, 둘 다 받을 수 있는지. 또 내가 지금 어떤 거에 가입돼 있는지도 궁금할 것 같은데, 처음에 상황을 말하는 것에 따라 시나리오 형태로 바로 말해버리니 이게 잘못된 것 같아.

## 핵심 목표
- 판정 직행 대신 **가입현황을 먼저** 보여주고, 다중 실손 시 **비례분담(이중 수령 불가)**을 정확히 설명한다. (실손 전용 유지)

## 사용자 시나리오
1. 사용자가 본인확인을 마치면 **보유한 실손 목록**을 먼저 본다.
2. 실손이 여러 개면 "중복이라도 비례로 나눠 지급(이중 수령 불가)"라는 안내를 본다.
3. 어떤 보험 기준으로 확인할지 대표 1건을 고른 뒤 상황을 입력한다.
4. 그 보험 기준으로 청구 가능성 안내를 받는다.

## 기능 목록
| # | 기능 | 우선순위 | 설명 | 상태 |
|:--|:--|:--|:--|:--|
| F-1 | 다중 실손 데모 데이터 | 필수 | 일부 페르소나 실손 2건+ (단건도 유지) | 미시작 |
| F-2 | 가입현황 화면 | 필수 | 보유 실손 리스트 + 대표 1건 선택 | 미시작 |
| F-3 | 플로우 재배치 | 필수 | 본인확인→가입현황→상황→안내 | 미시작 |
| F-4 | 비례분담 설명 | 필수 | 다건 시 결정론 카피 배너 + 챗봇 도메인 사실 보강 | 미시작 |
| F-5 | 스텝퍼/레일 동기화 | 필수 | PreStepper·ChatPage rail 라벨 재배치 | 미시작 |

## 기술 결정
- 스코프 L1: SlotState·coverage 엔진·인텐트 라우팅 불변(판정은 선택 1건 기준). 근거: PM-36.

## 비고
- 파킹랏: L2 대화형 가입현황 조회 인텐트, L3 보험사별 다중판정+비례 안분 수치.
