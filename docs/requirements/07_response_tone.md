# REQ-07: 응답 톤 정책 — 능동적 안내 + 정보 부족 시 부드러운 범용 멘트

- 요청일: 2026-05-24
- 상태: 분석 중
- 스프린트: 7

## 요청 원문
> "지금 너무 좀 막 말하는것 같아. 오히려 말투를 좀 어떤 정보가 있으면 정확하게 알려드리겠다. 하고 잘 모른다고 하면 정확한 정보가 아닌 대략적인 범용적인 정보를 준다고 해요"

(Sprint 6 시연 화면: "어제 빙판에 미끄러져 발목 골절로 입원했어요. 청구 가능한가요?" 입력 → "입력하신 정보로 매칭되는 약관 조항을 찾지 못했습니다. 보험사명과 상품명을 다시 한 번 정확히 확인해 주시겠어요? (현재: 보험사=미입력, 상품=미입력)" 출력)

## 핵심 목표

- 사용자에게 책임을 떠넘기는 어조 ("다시 확인해 주세요") 제거
- 시스템이 능동적으로 안내하는 어조 ("정확한 답변을 위해 X 정보가 있으면 더 좋습니다" / "현재 정보만으로는 일반적인 약관 기준으로 안내드리겠습니다")
- ask / no_match / partial / assessment 4 종 응답 모두 톤 일관

## 사용자 시나리오

1. **첫 턴 + 정보 부족 + RAG 0건**: 사용자 → "어제 빙판에 미끄러져 발목 골절로 입원했어요. 청구 가능한가요?"
   - 현재: "입력하신 정보로 매칭되는 약관 조항을 찾지 못했습니다. 보험사명과 상품명을 다시 한 번 정확히 확인해 주시겠어요?"
   - 보완 후: "정확한 청구 가능성 판단에는 가입하신 보험사·상품 정보가 필요합니다. 알고 계신 정보가 있다면 알려주시면 정확하게 안내드리겠습니다. (예: 한화손해보험 자동차보험 등)"

2. **추가 정보 요청 (ask)**: missing 슬롯 있을 때
   - 현재 (LLM): 단순 정보 요청 어조
   - 보완 후: "정확한 안내를 위해 다음 정보를 확인하고 싶습니다 — {slot 한국어 명}"

3. **partial 모드 (Sprint 6)**: 정보 일부 부족, 추정 답변
   - 현재: "제공된 정보가 일부 부족하여 추정 기반 답변입니다."
   - 보완 후: "정확한 답변에는 {부족 슬롯} 정보가 더 있으면 좋겠으나, 현재 정보로 일반적인 약관 기준에 따라 안내드리겠습니다."

## 기술 결정

- **새 LLM 호출 없음** — 기존 시스템 프롬프트 텍스트 + 1 함수 메시지만 수정. LLM 토큰 ~150 추가 (시스템 프롬프트), 호출 횟수 0 증가
- **RAG ≥ 1 강제 유지** — citation 없는 답변은 환각 위험 ↑. Sprint 6 결정 5 유지. "범용 안내" 는 멘트만, 실제 답변은 여전히 RAG 결과 기반
- **back-compat 0** — 응답 schema 무변경 (`AssistantAsk.message` 텍스트만 다름)
- **frontend 변경 없음** — `_build_no_match_ask` 가 만드는 `AssistantAsk` 그대로 표시됨
