# REQ-01: 보험청구심사 어시스턴트

- 요청일: 2026-05-22
- 상태: 설계 중
- 스프린트: 1

## 요청 원문
> 이번에 보험청구심사 에이전트를 개발하고자해. 각 보험사다마 자신들의 상품을 등록하자나. 그걸 이용해서 사용자들이 자신이 청구심사를 통과할까? 했을때 그걸 정확하게 된다 안된다 수준보다 어시스턴트 느낌으로 될 가능성이 높다. 안될가능성이 높다. 그때 이유들을 제시해서 할 수 있는 대국민 서비스를 만들고 싶어.

## 핵심 목표
- 일반 국민이 자신의 청구 시나리오를 자연어로 입력하면, **가능성 등급(높음/중간/낮음) + 근거 약관 조항 인용**을 어시스턴트 톤으로 제시한다.
- 단정적 판단("된다/안된다") 대신 충족·미충족 항목을 정리해 사용자가 직접 판단할 수 있게 돕는다.

## 사용자 시나리오
1. 일반 국민이 사이트 접속 → 면책 문구 확인 → 비로그인 채팅 진입
2. "어제 빙판에 미끄러져 발목 골절로 입원했어요. 보험금 받을 수 있나요?" 같은 자연어로 시작
3. 어시스턴트가 후속 질문으로 정보 보강 (가입 보험사/상품, 입원 일수, 진단명, 사고 경위 등)
4. 어시스턴트가 충분히 모았다고 판단하면 약관 조항 검색 → **가능성 등급 + 근거 조항 + 충족/미충족 항목** 응답
5. 매 응답에 "본 결과는 참고용이며 최종 판단을 대체하지 않습니다" 면책 문구 노출
6. 세션 종료 시 입력 정보 휘발

## 비기능 요구사항
- **법적 포지셔닝**: 보조 도구임을 명시. 최종 청구 가능 여부 판단을 대체하지 않음.
- **개인정보 보호**: 비로그인, 세션 휘발성, 입력값 서버 영구 저장 금지.
- **응답 신뢰성**: 가능성 등급 옆에 인용 조항 원문을 함께 노출. 출처 없는 단정 금지.
- **확장성**: 데이터 수집 방식(수동/크롤링)을 갈아끼울 수 있도록 파이프라인 격리.

## PoC 범위
- 보험 영역: **자동차보험 + 상해/질병(장기보험)** 두 영역
- 보험사: 임의 2곳 (Sprint 1에서 PDF 입수 가능한 보험사로 확정)
- 데이터: 보험사 공시실에서 수동 다운로드한 PDF 3종(상품요약/사업방법/약관)을 폴더 적재
- 배포: 내부 PoC / 시연 수준

## 기술 결정 (요약 — 상세는 docs/design/tech-decisions.md)
- 백엔드: Python + FastAPI (가정, tech-decision에서 확정)
- AI: RAG (임베딩 검색 + LLM 응답 생성)
- 벡터 DB / LLM / 임베딩 / PDF 파서: tech-decision에서 결정
- 프론트: Sprint 3에서 결정 (간단한 채팅 UI)

## 리스크 (분석 단계 식별)
1. 약관 PDF 파싱 품질 (표/특약/별표 구조) — Sprint 1 초반 검증 필수
2. 응답 신뢰도 — 인용 조항 원문 항상 노출로 완화
3. 멀티턴 종료 조건 — Sprint 2 설계에서 명시
4. 개인정보 — 세션 휘발성 + 서버 저장 금지
5. 크롤링 (Sprint 4 진입 시) — robots.txt / 약관 검토 선행

## 비고
- 첫 세션 분석에서 사용자의 핵심 인사이트: "크롤링보다 먼저 폴더의 PDF로 데이터 파이프라인을 개발"하자는 결정 → PoC 리스크 격리에 결정적.
- 공시 4단계 셀렉터(상품군 → 상품명 → 판매기간 → PDF) 구조 확인 (첨부 이미지).
